# rsTimes 0.2.0b3

This beta brings the adopted Polars implementation, exact Delta nanoseconds,
and ordinary/free-threaded Python support into the public distribution.
The four public classes are `Delta`, `Pydt`, `Pddt` and `Pldt`.

## Added

- `Pldt`, a real `polars.Series` subclass, with `.pldt` on Series and Expr.
  Expr operations return native `polars.Expr` and work in DataFrame/LazyFrame
  queries. Shared Rust calendar rules retain Polars units, independent null
  validity and the valid signed-int64 minimum.
- Relative `Delta(nanoseconds=...)` and absolute `Delta(nanosecond=...)`.
  Exact nanoseconds survive Delta arithmetic, state and Pddt/Pldt projection;
  datetime/Pydt/timedelta projection applies the documented final rounding.
- Distinct rsTimes wheels for CPython 3.14t and 3.15t, using the same source as
  ordinary CPython 3.12–3.15. With compatible upstream dependencies, imports
  and actual work keep the GIL disabled without a separate rsTimes mode.
- Pyright as the sole development type checker, covering installed public
  stubs, the native boundary, active implementations/tools and deliberate
  positive/negative examples. Node and Pyright are not runtime dependencies.

## Fixed and refined

- Pldt pandas Arrow timestamp inputs preserve units, nanoseconds, time zone,
  independent validity and the valid int64 minimum through supported factories,
  combination, subtraction and difference operations.
- NumPy exports consistently check the actual target dates, precision, missing
  values, capacity and NaT collisions, including forwarding subclasses and
  actual external exporters. Real callbacks execute once and keep their
  results or original exceptions.
- The NumPy validation loop uses typed iteration and prepares unit conversion
  once, while retaining the complete checks. Historical local timings remain
  bound to their measured artifacts; this release does not claim a single
  speedup ratio for every API or platform.
- Copy/state callbacks, returned validity, real class definitions, error
  previews, thread-test deadlines and carrier-unit documentation include the
  adopted review fixes.

## Upgrade notes

- Date-field replacement is `x.pddt.replace(...)` for Pddt and
  `x.pldt.replace(...)` for Pldt/Polars expressions. Host `replace` methods keep
  their native value-replacement meaning where the host provides them.
- Delta's versioned nanosecond state does not automatically migrate the old
  microsecond-only state format. Preserve original serialized data and
  explicitly recreate values when moving between these beta formats.
- Explicit date construction and ordinary fixed-unit operations do not silently
  lose precision or change the unit to make a result fit. Use `as_unit()` when
  an intentional conversion is needed.
- Install optional integrations before starting Python. Missing optional
  dependencies are not silently downloaded by rsTimes; installing one into an
  already running interpreter requires a restart.

## Supported distribution matrix

The distribution targets 48 native wheels and one complete source archive:

- Ordinary CPython 3.12, 3.13, 3.14 and 3.15 on macOS ARM64/Intel, Windows
  x86_64/ARM64, and Linux x86_64/ARM64 with glibc 2.28 or musl 1.2.
- Free-threaded CPython 3.14t and 3.15t on the same eight platform categories.
- No 32-bit, PyPy, universal2 or CPython 3.13t support is promised.

Default dependencies remain NumPy >=2.5.3 and, on Windows, tzdata >=2026.5.
dateutil, pandas and Polars remain optional. Ordinary pandas 2 compatibility
has its existing version/platform limits; the t qualification uses pandas 3.
See [installation and dependencies](../../README.md#installation-and-dependencies).

**Free-threaded Polars remains an upstream dependency condition.** The internally
qualified version is the fixed unmodified official Polars 2.1.0 source.
rsTimes does not maintain a Polars fork or distribute a self-built runtime.
Internal source-build validation does not mean an official t runtime wheel is
publicly available for every platform. Users obtain a compatible upstream
runtime themselves. See the [free-threaded guide](../free-threaded-python.md)
for the actual ABI, GIL and minimum-OS checks.

## Known deferred protocol cases

These previously reviewed cases remain explicitly deferred in this beta:

- A business `ZoneInfo` subclass that changes time-zone semantics can be
  interpreted by its key when used as a Pldt target zone (RV03). Use a standard
  supported ZoneInfo/timezone target rather than such an override.
- Named Pddt/Pldt `copy()` does not cover every custom reduction fallback or
  dynamically supplied reducer supported by standard-library copy (RV04).
  The standard-library `copy.copy`/`copy.deepcopy` protocol is the relevant
  alternative for these custom classes.
- A deliberately customized string-subclass type name can still run a display
  hook on certain error-preview paths and mask the original error (RV05).

These are not reported as repaired. Normal standard zones, ordinary state and
the adopted exporter checks retain their existing protection.

## Release verification and provenance

Publication requires a successful exact-source full matrix, actual installed
wheel tests, independent representative sdist rebuilds, and the frozen current-
baseline performance contract. A pushed annotated tag is the only publishing
trigger. GitHub Release and PyPI receive the same tested files, without a
publication-stage rebuild; PyPI uses Trusted Publishing/OIDC.

The release assets include `release-manifest.json`, `SHA256SUMS` and
`performance-receipt.json`. Those identify the actual source, each wheel/native,
the selected CI run and the scoped performance results. Public-download install
verification is a separate required stage; configuration alone is not proof of
publication or installation success.
