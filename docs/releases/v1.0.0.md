# rsTimes 1.0.0

The first stable rsTimes release brings the calendar and parsing APIs used in the beta series into one distribution. Use `Delta` to move a billing date by a month, `Pydt` and `parse_str` for individual dates, `Pddt` for pandas indexes, and `Pldt` for Polars Series and expressions. These APIs, nanosecond arithmetic for supported values, and free-threaded wheels were already available in 0.2.0b3.

## Upgrade from 0.2.0b3

```sh
python -m pip install --upgrade "rsTimes==1.0.0"
```

Keep the extras you use, for example `python -m pip install --upgrade "rsTimes[pandas,polars]==1.0.0"`. The basic `python -m pip install rsTimes` command also selects the stable release. Update any dependency pin that still names a beta before upgrading.

### Changes to check

- **Calendar ranges.** `Pddt.date_range` and `Pldt.date_range` preserve subsecond workday and work-month offsets and apply the calendar bounds consistently. Start a range on Saturday, January 13, 2024 at 23:00 with a normalized `BusinessDay` or `CustomBusinessDay` offset of two hours. Its first point is Tuesday, January 16 at midnight. If your code assumes that every custom business-frequency range with `periods=0` is empty, check that case with your actual endpoints. Some rules can roll and infer the same endpoint.
- **ISO, precision, and missing values.** The ISO factories consistently interpret supported compact clocks and ISO week dates, including inputs with a negative UTC offset. `Pddt.fromdatetime64` preserves a supported declared unit when broadcasting a typed `NaT`. A requested output unit that cannot represent a valid value raises an error. Convert units explicitly when the application intends to lose precision.
- **Python text and configuration.** Date parsing reads the stored text of real `str` objects and their subclasses. Call `str(value)` before passing a subclass if its `__str__` is supposed to transform the input. Create a fresh `Configs` to change its read-only options. Calling `__init__` again leaves the instance in its existing state, and `reset_settings()` resets the vocabulary while keeping the options.
- **Numeric text.** `parse_to_integer` and `parse_to_float` are new public functions. Use them for numeric tokens, including explicit grouping when appropriate. See [numeric parsing](../NumericParsing.md) for examples and limits.
- **Copying and state.** Copying and restoring dates and `Delta` objects honor the documented subclass hooks and preserve their original exceptions. If a subclass defines custom state, check its copy and pickle behavior during the upgrade.
- **Polars time zones.** A custom target time zone that Polars cannot represent reliably raises `ValueError`. Pass a standard supported zone for the target. For a supported aware source, rsTimes uses the source's actual instant when converting it.

The documented public APIs and type stubs describe the 1.0 interface. `Pydt` uses Python `datetime` precision and year limits; pandas and Polars date containers have their own unit and capacity constraints. Read [the type-checking guide](../type-checking.md) for the supported typed interfaces. Use pickle only for trusted data and check the documented state format if persisting custom subclasses.

## Supported interpreters and platforms

| CPython ABI | 64-bit platforms |
| --- | --- |
| 3.12, 3.13, 3.14, 3.15 | macOS ARM64 and Intel, Windows ARM64 and x86-64, Linux x86-64 and ARM64 with either glibc 2.28+ or musl 1.2+ |
| 3.14t, 3.15t | The same platform matrix with the matching free-threaded wheel |

A source distribution is also available. The macOS wheel target is macOS 11 or later, with macOS 14 or later for free-threaded Intel wheels. NumPy 2.5.3 or newer is required, with `tzdata` 2026.5 or newer on Windows. `python-dateutil` is optional for its adapters. `Pddt` requires pandas, with a minimum of 2.3.3 on the supported ordinary configurations that can use pandas 2. Windows ARM64 and Python 3.15 require pandas 3.0.6 or newer for that extra. Free-threaded pandas qualification uses pandas 3.0.6.

The Polars extra requires Polars 2.0.0 or newer. Free-threaded use requires a compatible upstream Polars runtime. Qualification uses the official Polars 2.1.0 source, and its internal CI builds are kept outside the rsTimes distributions. Upstream dependencies can raise the effective OS minimum. See the [free-threaded setup](../free-threaded-python.md) for the measured dependency profiles and how to check whether the GIL remains disabled.

For examples, start with the [README](../../README.md). Include the rsTimes version, Python ABI, dependency versions, and a small reproducer when [reporting an issue](https://github.com/AresJef/rsTimes/issues).
