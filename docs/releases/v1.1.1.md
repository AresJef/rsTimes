# rsTimes 1.1.1

This release corrects semi-month ranges and improves error locations for wide integer inputs in Polars. It also reduces work in selected unit conversions, fractional-second truncation, and ISO text parsing.

## Upgrade

```sh
python -m pip install --upgrade "rsTimes==1.1.1"
```

Keep the extras you use, such as `rsTimes[pandas,polars]==1.1.1`. The dependency minimums and supported Python versions are the same as in 1.1.0.

## Correctness

- `Pldt.date_range` now rejects a semi-month-start anchor outside days 2 through 27. Semi-month-end continues to accept days 1 through 27.
- Wide integer inputs report the first value outside the supported range. Eager calls report the row, and Polars expressions report the position within the batch they receive.

```python
from rstimes import Pldt

dates = Pldt.date_range("2024-01-01", periods=3, freq="SME-1", unit="us")
print(dates.cast(str).to_list())
# ['2024-01-01 00:00:00.000000', '2024-01-31 00:00:00.000000', '2024-02-01 00:00:00.000000']
```

## Performance and behavior

- The Pldt method and Polars Series and Expr accessors share the unit conversion kernel. They preserve nulls and time zones and continue to check precision and capacity.
- `Pddt.fsp` skips truncation when the input unit already fits the requested precision.
- Parsing ordinary ISO strings into a time-zone-naive Polars column takes a shorter output path.
- Pddt and Pldt reuse their copy reconstruction logic, and Polars localization reuses prepared time-zone information.

## Distribution

Wheels cover 64-bit CPython 3.12 through 3.15, including 3.14t and 3.15t, on macOS ARM64 and Intel, Windows ARM64 and x86-64, and Linux ARM64 and x86-64 with glibc 2.28+ or musl 1.2+. A source distribution is available. Free-threaded operation requires compatible upstream dependencies.
