**已完成并本地采用 `0.1.0+pddt.1/final06`。** 全部必要功能、构建和性能严格通过；源码、类型提示、文档与四个demo已同步。未发布、未推送、未提交。

## 本轮交付内容

`Pddt` 是真正的 `pandas.DatetimeIndex` 子类：保留 pandas 的索引、切片、DataFrame 集成与标准日期操作，同时增加批量年月调整、日历边界、多语言配置解析等便利方法。常用路径直接在 Rust 中处理整数和日期字段，不逐行生成 Python datetime。

`parse_epoch()` 接受一个日期时间值，返回指定 `s/ms/us/ns` 单位的 Python 整数。它与 `parse()` 支持的主要输入一致，增加纳秒保留和单值 Polars Datetime Series；多行由 Pddt 接收。普通字符串解析与原有 Parser 共享扫描、配置和日期规则。

| 能力 | 本轮做法与结果 |
|---|---|
| 原版公开能力 | 125 个公开定义逐项映射；106 个显式成员，其余使用 pandas 标准成员。映射不等于125个接口原样不变 |
| 四种单位 | 构造前选择目标；带单位输入按原单位换算，显式构造拒绝精度损失；`.as_unit()` 可主动降低精度 |
| 默认单位 | 固定为本轮核实的 pandas 3.0 行为，即使运行在 pandas 2.0；普通文本/datetime 通常 us，原生数组保留单位 |
| 日历与批量运算 | Rust 一次处理整列；年月夹取月底，周日与时钟规则明确，NaT 继续为缺失 |
| 纳秒超界 | 便利日历操作在真实结果超界时整列退到 us；实际损失精度才提示，us 也超界则安全报错 |
| 标准属性与输出 | date/time/timetz、闰年和月天数保持 pandas 属性；数值查询与 diff 返回普通 Index，isocalendar 使用标准列 |
| 时区与夏令时 | 日历修改按当地时间；重复/缺失时刻默认报错，支持明确策略；纯转换保留瞬间 |
| Configs | 文本确实使用显式传入的词表；不另写一套月份、星期或语言规则 |
| Polars | 可选依赖；Datetime ms/us/ns、时区、null、多块列直接读取数组；不逐项生成 Python datetime |
| 状态与复制 | 保留值、单位、时区、name、有效freq和正常类身份；不增加任意子类附加属性迁移框架 |
| 类型提示与说明 | Pddt/parse_epoch 的公开签名、英文 docstring、使用指南与演示；有限小数字段和整数 size 区分 |

明确格式的 `Pddt.strptime(..., fmt=...)` 复用标准库格式语法，会产生 datetime 中间结果；这是显式格式兼容路径，普通文本和 parse_epoch 仍使用 Rust 字段结果。

## 本轮发现并修正的问题

1. pandas 2.0 的单位转换参数不同：采用薄适配，显式构造依然检查无损，不经 ns 中转宽日期。
2. NumPy 超大 W/D 倍数曾使中间乘法回绕：改为受检运算，超界明确报错。
3. 星期/周期谓词原先通过构造目标日期判断，可能无故触发夏令时错误：改为直接查看当地字段。
4. 严格 ISO 工厂对无效第53周、非闰年第366天及小时格式存在缺口：独立限制 ISO 入口，不更改原 parse_str 的批准语法。
5. 命名数字工厂中的 NumPy 整数曾先变 float：改为整数读取，保留超过2**53的低位。
6. pandas 3 将真实 Timestamp/Timedelta 的公开模块名改为 `pandas`，旧 Delta 识别门会漏掉并丢失纳秒：本轮仅补齐模块提示，仍验证真实类型，恢复已有纳秒约定。新旧包在同 pandas3 原本一致，故这不是本轮引入的回归；修复与原始差异均保留。
7. Polars 无 null 列原先仍执行整数转换和缺失填充：直接使用其公开数组导出；有 null 路径保持受控整数填充。
8. diff 接收已有标准 DatetimeIndex 时曾重复包装 Pddt：直接读取该标准索引的值、单位与时区，保留长度、缺失和混合时区检查。
9. 极端自定义时区偏移可能在范围验证前整数回绕：用宽整数完整合计后检查严格±24小时，正负极值均明确报错。final04已采数据和失败证据保留，新final06重新绑定全部验收。

完整讨论、审查与批准边界保存在本轮 Astra 记录中；公开 docstring 只讲用户需要的规则，不引用内部源码。

## 完整性能结果

27项必要场景全部严格通过，15项观察场景全部收齐；无性能或质量豁免。核心日历组合两轮速度比为 **1.9204／1.9241倍**，保守结果为 **1.9106／1.9101倍**，超过1.50倍目标。

速度比＝对照耗时÷Rust耗时；大于1表示Rust更快。表中时间为主轮每次完整调用的微秒数，倍率来自紧邻配对统计。创建和日历场景通常每次处理1024个元素，单位转换和NumPy包装每次10000个；它们不是单元素耗时。观察项不作性能否决，但慢项照实报告。

必要项目逐项中位和保守耗时增幅均不超过5%；最差保守耗时增加约 **3.22%**。控制精度最大 **2.942%**，正式组间/顺序/跨轮波动最大 **4.315%**。9072个完整配对、9159次尝试、87组按预定规则排除、108个真实工作进程，全部原始数据保留。

cyTimes不支持本轮pandas3环境，因此日历对照双方统一在pandas2.3.3环境运行；不把它与pandas3时间拼为一个总体倍率。旧模块保护双方统一使用相同pandas3/NumPy依赖。

### 怎样理解这些结果

- 1024条普通文本、指定单位文本和Python日期列表创建均明显快于本轮pandas3对照；真正的单位转换保持接近pandas原生速度。
- 已有Index与原生NumPy数组的同单位包装，Rust路径仍有额外固定开销；Polars输入也比这里的直接pandas公开表达式慢。这些是原定观察项，不能据此宣称所有入口都更快。
- 15个观察项中的pandas日历表达式只代表这里冻结的等价调用，不表示pandas所有写法或所有数据分布都会获得相同倍率。
- 旧Parser ISO保护曾在final05稳定超标；第一次无收益改法已撤回，随后有真实重复读取证据的小数digit-run简化在final06正式通过。没有用换批长、删慢样本或改门槛消除该稳定失败。
