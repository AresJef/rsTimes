# Handling errors

Import the two specific parsing and configuration errors from `rstimes.errors`:

```python
from rstimes import Configs, parse_str
from rstimes.errors import ParseError, ConfigError, RstimesError

try:
    parse_str("2024-02-30", strict=True)
except ParseError as error:
    assert "day" in str(error)

try:
    Configs().add_month("harvest", 13)
except ConfigError as error:
    assert "month" in str(error)
```

`ParseError` and `ConfigError` are both `ValueError` subclasses. They also share
`RstimesError`, so applications can catch those two domain errors together.
`RstimesError` does not catch every possible failure from the library.

| Exception | Meaning |
| --- | --- |
| `TypeError` | An argument has an unsupported type, such as `Delta(hour=9.0)`. |
| `ValueError` | The type is accepted but the value is invalid, such as `Delta(hour=24)`. |
| `OverflowError` | A conversion or calculation exceeds its supported range. |
| `ParseError` | Text cannot be interpreted under the requested rules, including invalid strict fields or conflicts. |
| `ConfigError` | A token, mapped value, rule combination or registered region cannot be used. |
| `RuntimeError` | An unexpected internal library failure. A callback can also raise its own RuntimeError. |
| `ImportError` | A requested optional feature needs an unavailable package. The message gives an installation hint. |

NaN is `ValueError` for a scalar seconds conversion. Infinite seconds are
`OverflowError`. A required scalar input of `None` is `TypeError`; a date NaT
that cannot yield a scalar date is `ValueError`. Parameters that explicitly
allow `None` keep their documented meaning. Existing Pddt missing elements
remain supported.

## Understand the failed call

Library messages identify the public call and the known argument, field or
position. For example, an invalid strict minute identifies `parse_str`,
`minute` and its allowed range. A batch failure identifies `values[1]` or
`data[1]`, counting from zero. A failure while reading the next iterator item
is described as a read failure, rather than as an element that was already
obtained.

Input previews are bounded. Long strings show their original length; custom
objects are summarized by type without calling their display methods. This
limit applies to each library input preview, not to a user's own exception
message or the entire traceback.

## Errors from your own code

If a numeric conversion, date constructor, comparison or timezone method
raises an exception, its original exception object is propagated. Its type,
arguments, custom attributes, existing notes and cause are preserved. A
standard exception note may identify the rsTimes call that was being performed.
`str(error)` therefore continues to show the callback's original message.

The library does not retry the failing callback, replay an iterator, return a
partial batch, or undo side effects that your callback already performed.
Memory failures, interruption, exit and cancellation signals propagate without
an explanatory note. Unsupported operators may return `NotImplemented` so
Python can try the other operand; a genuine callback failure is not treated as
an unsupported operator.

## Saved state and timezone data

Malformed saved containers raise `TypeError`; invalid versions or noncanonical
saved fields raise `ValueError`. Invalid Configs token rules raise
`ConfigError`. A saved hash cache is a hint, not the object's value, and is
recomputed when necessary. Only load pickle data from trusted sources.

A Configs restore can issue one `RuntimeWarning` if registered timezone data
is unavailable. It retains the names and the other usable rules; it does not
substitute UTC. Parsing text that requires an unavailable region then fails
clearly. If warnings are configured as exceptions, restoration fails before
committing the new configuration.

There are no old exception-name aliases. Use standard Python exceptions or
these three classes from `rstimes.errors`.


### Exceptions from integer and truth conversion

An object without the required integer protocol receives a field-specific TypeError. If its real `__index__()` runs and raises, its exception object, arguments, cause and custom attributes are retained; the library does not format or reconstruct that exception. Boolean-option truth conversions follow the same rule. Memory errors and interruption or cancellation signals propagate without extra notes.
