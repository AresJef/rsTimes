# Configs 与 parse 的 Rust 重构验收

本轮已完成本地交付，最终版本为 **0.1.0+parser.1（final01）**。功能、构建和两轮正式性能验收通过；未发布。

本轮目标：保持冻结的 cyTimes 3.1.0 的 Configs 和 parse 调用方式及结果，普通解析由 Rust 完成，动态 Python 行为保留适配。原版可能崩溃或整数回绕的已知输入改为明确错误。

## 功能交付

```python
from rstimes import Configs, parse

parse("2024-02-29")
rules = Configs(dayfirst=True)
rules.add_month("harvest", 10)
parse("14 harvest 2026", cfg=rules)
```

## 明确的行为差异

| 情况 | rsTimes 行为 |
| --- | --- |
| 极长日期整数或小数累加溢出 | ParserFailedError，原因是 OverflowError |
| 时区的必要中间计算越界 | OverflowError |
| 恢复配置时状态长度或类型不正确 | ValueError 或 TypeError，先检查再读取 |
| 动态 weekday 返回极小整数，日期调整会溢出 | ParserFailedError，原因是 OverflowError |
| 模块路径和本包 pickle 路径 | 使用 rstimes.parser / rstimes.errors |

安全预期见 [批准差异](../tasks/evidence/parser-rust-rewrite-20261014/approved-differences.json)。已知会造成原版不安全执行的输入没有再次运行原版。

## 性能口径与当前状态

- 36 个代表 parse 调用等权组合：主轮及独立轮分别至少为原版的 1.50 倍。
- 36 个 parse、5 个兼容调用及3个既有 Delta 调用：各项中位及保守结果耗时增加不超过 5%。
- 17 个 Configs 独立调用只报告速度，不作为否决项；其功能及安全要求完整保留。
- 每项每轮 216 个完整配对，分布于9个真实新进程周期；两轮共432对。每个周期都有12个 AB 和12个 BA；统计按固定的三组进程汇总。
- 短长控制倍率差不超过3%；正式顺序、进程组及跨轮波动不超过5%。无效完整组回队，合格慢组保留。调用次数平均、配对数与真实进程重复分别统计。

正式验收 **通过**。主轮解析组合为 **1.8208倍**，独立轮为 **1.8244倍**；按该等权组合，耗时减少约45%。44项受保护调用的中位及保守结果、顺序／进程组／跨轮稳定性全部达标，0失败、0未明确。

原始两轮有1项B17波动6.19%未明确；经用户批准只将B17验证为约40ms窗口，短长精度差1.12%、预试过程差3.42%后，完整重采它的两轮。最终进程组波动为1.54%／2.72%。替代数据的速度比旧记录低，仍按约定采用；没有挑选更快成绩。其他未受影响的场景保留原配置和证据，按行保存实际来源和进程。

最终采用26352个完整配对；另保留被替代的432个旧B17配对。原始检查确认每场景每周期24对、AB／BA各12、实际进程身份、冻结质量规则和组跨度。全部旧无效尝试与失败预试保留。Delta每周期的两方分别由两个独立worker测量，未把controller冒充测量线程。

速度比＝对照耗时÷Rust耗时；大于1表示Rust更快，小于1表示Rust更慢。表中保留三位小数；保守值、单次平均耗时、波动和每行来源见[61项明细CSV](../tasks/evidence/parser-rust-rewrite-20261014/performance-details.csv)。Configs存在独立读取／修改变慢及波动，按用户已批准的取舍只报告速度，完整功能与安全验收不变。
